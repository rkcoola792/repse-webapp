# REPSE storefront

The storefront runs on Next.js App Router. Product listings and product detail content are rendered on the server and revalidated periodically. Product data is cached in the browser with TanStack Query; Redux continues to manage the cart, account, and wishlist state.

## Run locally

Use Node.js 20.9 or newer, then install dependencies and start Next.js:

```bash
npm ci
npm run dev
```

Configure these values in `.env`:

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | Browser API path, normally `/api` |
| `API_BASE_URL` | Backend origin used for server rendered product requests |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | Google sign-in client ID |
| `NEXT_PUBLIC_ORDER_DISCOUNT_PERCENT` | Checkout discount percentage |
| `NEXT_PUBLIC_ORDER_DELIVERY_FEE` | Checkout delivery fee |
| `NEXT_PUBLIC_SITE_URL` | Public storefront origin used in metadata and the sitemap |

The Next.js rewrite proxies `/api/*` to the backend configured in `next.config.js`. Update that destination if the backend host changes. Existing local Vite-prefixed values are still read for development; Render is configured with the `NEXT_PUBLIC_*` names above.

## Production

```bash
npm run lint
npm run build
npm start
```

The Render blueprint runs the storefront as a Node web service and includes the `/api` rewrite through Next.js. Product metadata, Product structured data, `robots.txt`, and `sitemap.xml` are generated by the App Router.
